## Decisions made this session

**Commission stored in basis points, not a float.** `Partner.commissionBps`
(800 = 8.00%). Integer math avoids float drift on money. Starter 800,
Professional 1200, Studio/Enterprise 1800 — see `PLAN_COMMISSION_BPS`.

**Partners log in with the existing magic-link provider.** `partnerProcedure`
matches `Partner.email` against the session email rather than checking a role,
so no changes to `lib/auth.ts` were needed. `Partner.ownerId` is backfilled the
first time an approved partner opens the dashboard.

**Partner management sits behind `operatorProcedure`, not `adminProcedure`.**
The operator runs day-to-day approvals; gating behind admin would have blocked
the actual workflow.

**Commission accrual is idempotent.** `@@unique([orderId, type])` on
`CreditTransaction` means an order can only ever produce one `COMMISSION` row.
Toggling an order in and out of `COMPLETE` cannot double-pay. The ledger write
and the `creditBalanceCents` increment share one transaction.

**Attribution is first-touch, 30 days.** An existing unexpired `ref` is never
overwritten, so a second partner cannot poach an attributed lead. Stored in
localStorage *and* a `SameSite=Lax` cookie so it survives the Stripe redirect.

**A bad `?ref=` can never break an order.** `resolvePartnerIdFromRef` returns
`null` for unknown, inactive, or malformed slugs — the order proceeds as direct.
